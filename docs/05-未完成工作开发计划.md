# 未完成工作开发计划

## 目标

优先完成一条真实业务闭环：

```text
登录
→ 项目
→ 上传和解析需求
→ AI 生成测试用例
→ 人工 Review
→ Jenkins 执行
→ 测试报告
→ AI 失败分析
```

## P0：必须优先完成

**当前状态：代码闭环已完成，等待真实 Jenkins 环境验收。**

P0 的目标是形成可验收的核心 MVP 闭环。

| 顺序 | 工作项 | 完成标准 |
|---|---|---|
| P0-1 | 建立正式工程基线 | 初始化 Git；补充环境配置；接入 Flyway 或等效数据库迁移机制；保留 H2 测试环境 |
| P0-2 | 测试用例数据模型 | 新增 `TestCase`、测试步骤、状态、优先级、类型、需求关联等实体及数据库表 |
| P0-3 | 测试用例 CRUD API | 支持创建、查询、详情、编辑、删除、分页和筛选 |
| P0-4 | 测试用例前端真实接入 | 测试用例页面移除静态数据，接入后端；支持新建、编辑、删除和筛选 |
| P0-5 | 测试用例状态流转 | 实现 `DRAFT → REVIEW → APPROVED`，支持人工 Review 和退回修改 |
| P0-6 | 需求详情和正文解析 | 增加需求详情接口；完成 PDF、DOCX 正文提取；保存解析失败原因 |
| P0-7 | AI 生成用例最小闭环 | 实现 AI 模型配置、Prompt 配置、模型调用、结构化 JSON 校验、Draft 保存 |
| P0-8 | 基础权限控制 | 支持管理员、测试开发角色；实现项目成员访问校验，禁止越权查看其他项目数据 |
| P0-9 | 自动化项目和 Jenkins 最小链路 | 保存 Git、Branch、Test Path、执行命令、Jenkins Job，并支持触发真实 Jenkins Build |
| P0-10 | 执行记录和基础报告 | 保存 Build、Commit、状态、日志地址、Allure 地址、开始时间、结束时间和测试统计 |
| P0-11 | P0 验收测试 | 完成接口测试、权限测试、主要异常测试，并跑通一条真实端到端流程 |

用户可以上传一份 PRD，生成测试用例 Draft，人工 Review 后保存正式用例，并通过 Jenkins 执行自动化测试，查看执行结果和报告。
