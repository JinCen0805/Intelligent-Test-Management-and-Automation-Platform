# 技术架构与工程边界

## 1. V1 架构

```text
Vue 3 + TypeScript + Element Plus
              ↓
Spring Boot 单体应用
              ↓
MySQL
       ↙       ↓        ↘
     Git     Jenkins     AI Provider
                ↓
       pytest / Playwright
                ↓
             Allure
```

V1 使用单体 Spring Boot 应用，不强制引入 Redis、消息队列、微服务或分布式调度。

## 2. 职责边界

### 平台

- 管理项目、需求、测试用例和测试任务；
- 管理接口测试工作台资产；
- 关联 Git Repository；
- 调用 Jenkins API；
- 保存执行记录；
- 展示日志、测试结果和 Allure 报告；
- 调用 AI 生成测试用例和分析失败结果。

### Git

Git Repository 是接口自动化和 UI 自动化代码的唯一事实来源。平台只保存仓库引用和执行配置，不保存完整代码作为事实来源。

### Jenkins

Jenkins 负责 CI/CD 调度、代码 Checkout、测试环境执行、pytest / Playwright 执行和结果回传。

### 测试开发工程师

测试开发工程师在本地 IDE 开发、调试和维护自动化代码，再提交到 Git。

## 3. 执行链路

```text
平台创建测试任务
  ↓
平台调用 Jenkins API
  ↓
Jenkins Build
  ↓
Git Checkout 指定 Branch
  ↓
pytest / Playwright
  ↓
Allure Results
  ↓
Jenkins 返回状态、日志和附件
  ↓
平台保存 TestExecution 和 TestReport
```

平台 Web Server 不直接执行用户自动化测试代码。

## 4. AI 边界

V1 只实现两个业务场景：

1. PRD 生成结构化测试用例 Draft；
2. 测试执行失败结果分析。

业务代码通过统一 Provider 接口调用模型：

```text
generate(prompt, model)
```

AI 不自动修改代码、不自动提交 Git，也不替代测试开发工程师的人工 Review。

## 5. 接口工作台边界

接口测试工作台用于轻量接口调试、请求集合、环境变量、断言和执行历史。

接口测试工作台不等于接口自动化代码项目：

- 工作台保存请求和集合资产；
- 正式回归代码仍由测试开发工程师在本地 IDE 维护；
- 正式代码通过 Git + Jenkins 执行；
- 平台不提供在线 IDE。
