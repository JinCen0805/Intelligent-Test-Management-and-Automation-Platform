## 2. 配置约定

### 2.1 Redis 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `REDIS_ENABLED` | `true` | 是否执行 Redis 健康检查 |
| `REDIS_REQUIRED` | `false` | Redis 故障是否令整体健康状态为 `DOWN` |
| `REDIS_HOST` | `127.0.0.1` | Redis 地址 |
| `REDIS_PORT` | `6379` | Redis 端口 |
| `REDIS_PASSWORD` | 空 | Redis 密码，生产通过环境变量或密钥管理注入 |
| `REDIS_DATABASE` | `0` | Redis DB 编号 |
| `REDIS_TIMEOUT` | `2s` | Redis 命令超时 |
| `REDIS_CONNECT_TIMEOUT` | `2s` | Redis 连接超时 |
| `REDIS_POOL_MAX_ACTIVE` | `16` | 连接池最大活动连接 |
| `REDIS_POOL_MAX_IDLE` | `8` | 连接池最大空闲连接 |
| `REDIS_POOL_MIN_IDLE` | `0` | 连接池最小空闲连接 |
| `REDIS_POOL_MAX_WAIT` | `1s` | 获取连接最大等待时间 |
| `REDIS_KEY_PREFIX` | `testpilot:` | 统一 Key 前缀 |

### 2.2 Security 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `TESTPILOT_SECURITY_HTTP_STATUS_ENFORCEMENT` | `true` | 开启后受保护接口返回 HTTP 401/403；测试 profile 显式关闭以保持阶段 0 API 包兼容 |

默认和 `mysql` profile 使用标准 HTTP 状态；`test` profile 使用兼容开关，阶段 3 完成认证切换后应删除该兼容分支。

## 3. 健康检查响应

`GET /api/health` 保留原有 `code/message/data` 外壳，并新增基础设施状态：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "service": "itmap-platform",
    "status": "UP",
    "checks": {
      "database": {"status": "UP", "product": "H2"},
      "redis": {"status": "DISABLED", "required": false}
    }
  }
}
```

当 `REDIS_REQUIRED=true` 且 Redis 不可用时，`data.status` 返回 `DOWN`，但健康接口仍返回统一 JSON，便于监控采集。

## 4. 安全行为

标准 HTTP 状态开关开启时：

- `/api/health`、`/api/auth/login`、Jenkins 回调和公共 Allure 下载放行；
- 未认证访问受保护 API 返回 HTTP 401，响应 `code=40100`；
- 已登录但不满足系统角色的用户访问管理员 API 返回 HTTP 403，响应 `code=40300`；
- 管理员访问用户管理 API 可以继续进入现有 Controller/Service；
- 业务层原有 `40100/40301/40302/40303` 判断暂时保留，避免阶段 1 改变业务语义。
