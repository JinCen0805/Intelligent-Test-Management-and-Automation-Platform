## 3. Repository 到 Mapper 迁移清单

当前全部 Repository 均继承 `JpaRepository`，没有 MyBatis Mapper。方法总量为 25 个 Repository、约 70 个派生查询方法，另有 1 个 JPQL 复杂查询和 4 个分页查询。

| 模块 | 当前 Repository | 重点查询/风险 | 建议实现 |
| --- | --- | --- | --- |
| 用户 | `UserRepository` | 用户名、状态、排序 | `BaseMapper<User>` + 唯一索引 |
| 项目 | `ProjectRepository` | 未删除项目、编码唯一 | Lambda 条件 + `deleted` 逻辑删除 |
| 项目成员 | `ProjectMemberRepository` | 成员唯一、角色读取、删除 | 唯一键 `(project_id,user_id)` |
| 需求 | `RequirementRepository` | 项目范围列表和详情 | Lambda 条件 |
| 测试用例 | `TestCaseRepository` | JPQL 搜索、分页、统计 | XML 搜索 + `Page<TestCase>` |
| API | `ApiCollectionRepository`、`ApiRequestRepository`、`ApiEnvironmentVariableRepository`、`ApiExecutionHistoryRepository` | 集合、请求、环境变量、分页历史 | 简单条件使用 Wrapper，历史分页保留排序 |
| 自动化 | `AutomationProjectRepository`、`TestTaskRepository`、`TestExecutionRepository`、`TestReportRepository` | 执行状态、时间范围、项目集合分页 | XML 处理统计和时间范围查询 |
| Jenkins | `JenkinsInstanceRepository`、`JenkinsPipelineBindingRepository`、`JenkinsCredentialGrantRepository` | 授权范围、Job 绑定、状态过滤 | Wrapper + XML 处理 Job 列表 |
| 引导 | `AutomationOnboardingRepository`、`AutomationOnboardingStepRepository` | 状态集合和步骤顺序 | Wrapper |
| AI | `AiModelRepository`、`PromptTemplateRepository`、`AiTaskRepository`、`AiAnalysisRecordRepository`、`AiAutomationTaskDraftRepository` | 启用模型、模板版本、异步任务状态 | Wrapper；任务 ID 保留 String |
| 审计 | `AiCallAuditRepository`、`OperationAuditRepository` | 按创建时间倒序、项目/用户索引 | XML 或 Wrapper，明确最大查询范围 |

### 3.1 复杂查询和分页登记

- `TestCaseRepository.search(...)`：当前存在 JPQL 查询，迁移时使用 XML 或动态条件 SQL，保持关键词、优先级、类型、状态和分页排序行为。
- `ApiExecutionHistoryRepository.findAllByProjectIdOrderByStartedAtDesc(..., Pageable)`：保持 `started_at DESC` 和总数。
- `TestExecutionRepository`：项目集合、状态、时间范围和分页组合查询，迁移时必须固定参数绑定和排序。
- `TestCaseService`、`ReportService`：当前由 Service 先查项目/执行记录，再组装 DTO，迁移时不要为了减少查询而改变响应结构。

## 4. 事务边界清单

当前存在 `@Transactional` 的主要服务范围如下：

- 用户：创建、修改、状态变更、重置密码。
- 项目：创建、修改、软删除；成员：新增、修改、删除。
- 需求：上传、解析。
- 测试用例：创建、修改、状态流转、删除。
- API 工作台：集合、请求、变量和执行历史写入。
- 自动化：项目、任务、执行、同步、重试、取消和结果写入。
- Jenkins：实例、绑定、凭证授权、引导流程。
- AI：任务提交、模型和 Prompt 管理、分析记录、草稿确认。
- 审计：`REQUIRES_NEW` 记录操作审计和 AI 调用审计。

迁移时重点保持：

1. 审计写入的 `REQUIRES_NEW` 语义；
2. 执行结果和报告写入的同一事务边界；
3. 异步 AI/Jenkins 任务在线程中重新建立事务；
4. 删除、状态流转和重试的并发行为；
5. 读操作不因 Mapper 改造误加写事务。

### 5.4 测试数据库差异

- 测试 profile 使用 H2 `MODE=MySQL` 内存库；
- Flyway 在测试启动时成功执行 V1-V17；
- 同时配置了 Hibernate `ddl-auto: create-drop`，导致测试仍依赖 ORM 自动建表，和目标原则存在差距；
- MySQL profile 使用环境变量 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`，当前仓库没有 Redis 连接配置或 Redis 启动脚本；
- `database/schema.sql` 与 Flyway 历史脚本存在字段演进差异，后续以 Flyway 为唯一结构来源。

## 6. Session、认证与权限现状

### 6.1 内存 Session 调用路径

```text
AuthController
  -> AuthService.login()
       -> UserRepository.findByUsernameAndStatus()
       -> UUID.randomUUID()
       -> ConcurrentHashMap<String, Session>.put()

所有受保护 Controller
  -> AuthService.currentUser(Authorization)
       -> Bearer 前缀检查
       -> ConcurrentHashMap 查 Token
       -> TTL 比较
       -> UserRepository.findByIdAndStatus()
```

登出路径为 `AuthController.logout -> AuthService.logout -> sessions.remove(token)`。当前 Token 是 UUID 随机字符串，不是 JWT；前端兼容约束是保留 `Authorization: Bearer <token>`。

### 6.2 当前角色

| 范围 | 当前值 | 使用位置 |
| --- | --- | --- |
| 系统 | `ADMIN` | 用户管理、AI 配置、审计、Jenkins 管理 |
| 系统 | `TEST_DEVELOPER` | 默认演示用户角色 |
| 项目 | `OWNER` | 项目负责人，代码中由 `Project.ownerId` 和成员展示共同表达 |
| 项目 | `MANAGER` | 项目写权限 |
| 项目 | `TEST_DEVELOPER` | 项目成员，可读，当前不能写 |

## 7. API 兼容性冻结清单

### 7.1 统一响应和错误约定

- 成功响应：`{"code":0,"message":"success","data":...}`。
- 业务失败通常仍返回 HTTP 200，由 `code` 表达错误。
- 未登录现状：`code=40100`，消息为“未登录”或“登录已失效”。
- 登录失败：`code=40101`。
- 项目无访问权限：`code=40301`。
- 项目无修改权限：`code=40302`。
- 管理员专属接口：`code=40303`。
- Jenkins 回调签名错误：`code=40102`。
- 参数校验：`code=40001`。
- 未处理异常：HTTP 200、`code=500`、消息为“服务暂时不可用”。

### 7.2 路径与认证边界

| API 分组 | 路径 | 认证/权限现状 | 响应冻结点 |
| --- | --- | --- | --- |
| 健康 | `GET /api/health` | 公开 | `data.service/status/timestamp` |
| 认证 | `/api/auth/login`、`/me`、`/logout` | login 公开，其余 Bearer | login 返回 `accessToken` 和 `user` |
| 项目 | `/api/projects/**` | Bearer；项目读/写边界 | 列表为数组，详情/写入为项目 DTO |
| 成员 | `/api/projects/{projectId}/members/**` | Bearer；项目写 | 成员包含用户和项目角色 |
| 需求 | `/api/projects/{projectId}/requirements/**` | Bearer；项目读/写 | 上传保留 multipart 和 `parseStatus` |
| 测试用例 | `/api/projects/{projectId}/test-cases/**` | Bearer；项目读/写 | 分页保留 `content/totalElements` |
| API 工作台 | `/api/projects/{projectId}/api-workbench/**` | Bearer；项目读/写 | 集合、请求、变量、执行历史路径不变 |
| 自动化 | `/api/projects/{projectId}/automation-projects/**`、`test-tasks/**`、`test-executions/**` | Bearer；项目读/写 | 执行状态、报告结构保持 |
| 报告 | `/api/reports/**` | Bearer；项目读；Allure 公共下载使用临时 Token | 报告中心和执行详情字段保持 |
| AI 项目任务 | `/api/projects/{projectId}/requirements/.../generate`、`automation-tasks/**`、`test-executions/.../analyze` | Bearer；项目读/写 | 异步任务返回 `taskId/status` |
| AI 管理 | `/api/ai/models/**`、`/api/ai/prompts/**` | Bearer；ADMIN | API Key 只返回配置状态，不回显明文 |
| AI 审计/任务 | `/api/ai/audits`、`/api/ai-tasks/{taskId}` | Bearer；审计 ADMIN，任务项目读 | 保留异步任务状态结构 |
| Jenkins 管理 | `/api/admin/jenkins-instances/**` | Bearer；ADMIN | Token 不回显，使用 `tokenConfigured` |
| Jenkins 回调 | `/api/integrations/jenkins/callback/{executionId}` | `X-Jenkins-Token` | 签名错误和成功响应码保持 |
| 操作审计 | `/api/operation-audits` | Bearer；ADMIN | 按创建时间倒序返回数组 |
| 用户管理 | `/api/users/**` | Bearer；ADMIN | 用户角色和状态字段保留兼容窗口 |

### 7.3 Bearer Token 兼容要求

后续认证切换必须继续接受：

```http
Authorization: Bearer <随机Token>
```

不得在阶段 1-3 强制前端改成 JWT，也不得改变登录响应中的 `data.accessToken` 字段名。

## 10. 阶段 0 回滚点

阶段 0 只新增文档、分支和基线 Smoke Test，没有改动业务运行逻辑。回滚方式：

1. 删除或停用 `codex/stage-0-baseline` 分支；
2. 保留当前主分支 `main` 的业务代码；
3. 不执行任何数据库迁移；
4. 不改变前端 API、认证 Token 或运行配置。
