## 1. 执行协议（AI 必须遵守）

### 1.1 推进规则
1. 严格按第 3 节阶段顺序执行；任务的前置依赖未通过，不开始下一个任务。
2. 每个任务 = 一次原子提交，提交信息 `fix(<scope>): <一句话>`，一个提交只做一件事。
3. 每个任务完成必须通过该任务的**验收命令**；失败则修复后重跑，禁止带病进入下一项。
4. 每个阶段结束运行全量门禁（见第 4 节），并把本文件状态表对应行改为 ✅。
5. 每个阶段结束后输出一段简短执行报告：改了什么、验证结果、剩余风险。

### 1.2 硬性禁止
- 不做与修复无关的重构、不改 UI 视觉、不升级框架、不引入新的运行时依赖（测试依赖除外）。
- 不删除现有业务功能；死代码清理仅限第 3 节明确列出的项。
- 不提交 `target/`、`node_modules/`、`dist/`、`*.log`、本地 `data/`。
- 不修改 `v2` 主线历史；修复统一在 `fix/review-2026-11` 分支进行，阶段验收后合回。
- 不覆盖用户本地配置（`scripts/local.env.ps1`）。

### 1.3 无法闭环项的处理
- 凡需要仓库外系统配合（Jenkins 流水线仓库、生产库变更窗口、独立域名）的，AI 实现**本仓库侧的开关与兼容逻辑 + 文档**，在状态表标记 `🔶 需人工配合`，不阻塞其他任务。
- 验证不了的部分（例如真实 Jenkins 回调、生产 MySQL），用 MockMvc/集成测试覆盖执行路径，并在阶段报告注明"需人工回归"。

### 1.4 已预决策（执行时不再询问，按此实现）
| 决策点 | 采用方案 |
| --- | --- |
| AI 契约方向 | 后端异步化：三个 Controller 接 `AiTaskService.submit*`，前端轮询保持不动 |
| local 端口 | 全项目统一 8080：删除 `application-local.yml` 的端口覆盖，脚本/vite 保持一致 |
| 首次部署管理员 | 新增 `AdminBootstrap`，空库时从环境变量创建管理员；local profile 仍保留演示数据 |
| 事务重构 | 用"短事务读 → 无事务调外部 → 短事务写"拆分，优先 AI 三个 Service，再自动化两处 |
| 回调签名 | 本仓库先实现 body-hash 双校验 + 配置开关（默认兼容旧签名），Jenkins 侧升级后切严格 |
| 外键约束 | 本次只补索引，不补外键（存量数据风险），列入需人工评估 |
| Allure 沙箱 | 本仓库先加 CSP 响应头与前端 `new URL()` scheme 校验；独立域名部署列入需人工 |
| God 类拆分 | 只做低风险拆分（AI 公共件、automation store 按域），不重写业务逻辑 |
